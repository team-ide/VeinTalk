# 集群与微服务部署（规划中，面向运维）

> ⚠️ 当前状态：**未适配**。本文为规划说明，内容可能随版本演进调整。当前请使用 [单机部署](02-单机部署.md)。

## 一、集群部署（规划中）

聚合服务（server-all）多进程水平扩展，解决单机性能瓶颈：

```
                     ┌────────────────────────────┐
客户端 ──► Nginx ──► │ 多接入网关 gateway          │
                     │ （多进程，共享会话状态）      │
                     └────────────┬───────────────┘
                                  │
        ┌─────────────────────────┼─────────────────────────┐
        ▼                         ▼                         ▼
 server-all（进程1）        server-all（进程2）        server-all（进程N）
        │                         │                         │
        └─────────────┬───────────┴─────────────┬───────────┘
                      ▼                         ▼
              ┌──────────────┐          ┌──────────────┐
              │ Redis（缓存） │          │ Kafka（队列） │
              └──────────────┘          └──────────────┘
                      │                         │
              ┌───────┴───────┐         ┌───────┴───────┐
              │ ZK（注册中心） │         │ etcd（配置中心）│
              └───────────────┘         └───────────────┘
                      └──────────┬──────────┘
                                 ▼
                    MySQL + MinIO + LiveKit + Nginx
```

要点：

- 各进程为相同的聚合服务，事件经 **Kafka** 广播，缓存与会话状态统一放 **Redis**
- 接入网关多实例，经 **ZK** 注册与寻址，客户端连接任意网关
- 动态配置经 **etcd** 下发（数据库、Redis、MinIO 等连接信息统一管理）
- 数据库、MinIO、LiveKit、Nginx 与单机部署相同

## 二、微服务部署（规划中）

各服务独立进程、独立部署与伸缩（gateway / user / chat / group / relation / media / system / platform / manage / stat）：

- 服务间经 gRPC 调用（协议已按 proto 定义，当前单机版为进程内调用）
- 注册中心 ZK、配置中心 etcd、缓存 Redis、队列 Kafka
- 按服务设置独立数据库（当前各服务已支持独立库配置）
- 适合大规模部署与按需伸缩，运维复杂度最高

## 三、前置依赖准备（供提前规划）

| 组件 | 用途 | 建议 |
|------|------|------|
| ZK | 服务注册与寻址 | 3 节点集群 |
| etcd | 动态配置中心 | 3 节点集群 |
| Redis | 缓存 / 会话 / 分布式锁 | 主从或集群 |
| Kafka | 事件队列（消息分发、状态同步） | 3 节点集群 |
| MySQL | 业务数据库 | 主从或集群 |
| MinIO / LiveKit / Nginx | 存储 / 音视频 / 入口 | 同单机部署 |

## 四、与单机部署的差异

| 项 | 单机部署 | 集群 / 微服务部署 |
|----|----------|-------------------|
| 服务调用 | 进程内直接调用 | gRPC 远程调用 |
| 事件分发 | 进程内广播 | Kafka 队列 |
| 缓存 | 内存（默认） | Redis |
| 动态配置 | 本地文件 | etcd |
| 服务发现 | — | ZK |
| 接入网关 | 单实例 | 多实例 |
| 部署方式 | docker-compose | 编排工具（K8s 等，规划中） |

## 五、迁移路径

1. **单机 → 集群**：开启 `CONFIG_MODE=etcd`、`CACHE_MODE=redis`，部署 ZK/etcd/Redis/Kafka，聚合服务多进程启动即可（平滑过渡）
2. **集群 → 微服务**：各服务拆分独立部署，按需伸缩
