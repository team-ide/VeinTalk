# 单机部署（面向运维）

单机部署为当前适配的部署方式：**docker-compose 一键启动**，共 6 个服务：im 聚合服务 + MySQL + MinIO + Redis（可选启用）+ LiveKit + Nginx。

## 一、交付物

| 文件 | 说明 |
|------|------|
| `vein-talk-aio:<版本>-<架构>.tar.gz` | 服务端镜像离线包（docker load 导入） |
| `docker-compose.yml` | 六容器编排 |
| 配置模板包 | `.env`、`server.env`、`nginx/`、`mysql/conf/`、`livekit/` 等 |

下载地址见 [下载中心](../05-版本发布/00-下载中心.md)。

## 二、环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Linux（amd64 / arm64） |
| Docker | 20.10+（推荐 24+，Compose v2） |
| 内存 | 建议 ≥ 4GB（MySQL + MinIO + LiveKit + im） |
| 磁盘 | 建议 ≥ 50GB（数据量增长主要来自数据库与 MinIO 文件） |
| 端口 | 见下方端口表（全部容器为 host 网络模式，端口直接占用宿主机） |

## 三、安装步骤

### 1. 导入镜像

```bash
docker load -i vein-talk-aio:1.0.0-test.1-amd64.tar.gz
```

### 2. 准备部署目录

解压配置包到宿主机 `/data/vein-talk/`（目录结构见下文），确认包含：

```
/data/vein-talk/
├── docker-compose.yml
├── .env                  # 部署参数（本机 IP、对外地址、各组件凭据）
├── nginx/
│   ├── nginx.conf
│   ├── conf.d/           # 站点与反代配置（path.conf 等）
│   ├── ssl/              # TLS 证书（测试证书见 测试证书说明）
│   └── html/             # 门户静态资源
├── mysql/
│   └── conf/my.cnf
├── livekit/
│   └── livekit.yaml
├── app/                  # 门户站点配置（data.json5 等，可选覆盖）
├── privacy.html          # 隐私政策页（可选覆盖）
├── data/                 # 服务端数据目录（自动创建）
└── logs/                 # 服务端日志目录（自动创建）
```

### 3. 修改配置

编辑 `.env`，按实际环境修改：

| 参数 | 说明 |
|------|------|
| `LOCAL_IP` | 本机（公网/内网）IP，LiveKit 等组件对外告知客户端使用 |
| `SERVER_URL` | 客户端访问服务端的完整地址（如 `https://vein-talk.com/vein-mobile/`，替换为你的域名） |
| `LIVE_URL` | LiveKit 对外地址（如 `https://your-domain.com/vein-live`） |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_USER` / `MYSQL_PASSWORD` | MySQL 凭据（首次启动创建库与用户） |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | MinIO 凭据 |
| `MINIO_SERVER_URL` | MinIO 本机地址（默认 `http://127.0.0.1:9000`） |
| `MINIO_UPLOAD_ENDPOINT` / `MINIO_DOWNLOAD_ENDPOINT` | 客户端上传 / 下载文件的对外地址 |
| `REDIS_PASSWORD` | Redis 密码（可选，缺省使用内存缓存） |

### 4. 启动

```bash
cd /data/vein-talk
docker compose up -d
```

> im 容器启动脚本会等待 MySQL、MinIO 就绪后自动启动服务（`start-im.sh`）。

### 5. 验证

```bash
# 容器状态（im 为 healthy 即正常）
docker compose ps

# 服务端日志
docker logs -f vein-im
```

访问验证（对外访问，域名不带端口）：

- 门户：`https://vein-talk.com`（替换为你的域名）
- 管理后台：`https://vein-talk.com/vein-manage`
- 公众平台：`https://vein-talk.com/vein-platform`
- 客户端接入：移动端「扫一扫」扫门户首页的服务器二维码即可添加本服务器

本机直连检查（可选）：

- 门户：`http://<服务器IP>:10101/`
- 移动端 Web 版：`http://<服务器IP>:30110/vein-mobile/`（对外访问时使用 `SERVER_URL` 配置的地址）
- 客户端 API：`http://<服务器IP>:30110/vein-gateway/check` 应返回正常响应

## 四、目录与挂载说明

所有容器数据均持久化在宿主机 `/data/vein-talk/` 下：

| 宿主机目录 | 容器内用途 |
|------------|------------|
| `mysql/data`、`mysql/logs`、`mysql/conf/my.cnf` | MySQL 数据、日志、配置 |
| `minio/data`、`minio/logs` | MinIO 对象数据、日志 |
| `redis/data` | Redis 持久化（AOF） |
| `livekit/livekit.yaml` | LiveKit 配置（端口、公网 IP、Redis、密钥） |
| `nginx/nginx.conf`、`nginx/conf.d`、`nginx/ssl`、`nginx/html`、`nginx/logs` | Nginx 配置、证书、静态资源、日志 |
| `data`、`logs` | im 服务端数据与日志 |
| `app`、`privacy.html` | 门户站点配置与隐私政策页（可覆盖镜像内置版本） |

## 五、配置说明

### 运行模式（im 服务环境变量）

| 变量 | 取值 | 说明 |
|------|------|------|
| `DEPLOY_MODE` | `standalone` | 单机部署模式 |
| `CONFIG_MODE` | `local` | 配置中心模式（集群部署时改 etcd） |
| `CACHE_MODE` | `local` / `redis` | 缓存模式：内存缓存 / Redis |
| `MEDIA_MODE` | `minio` | 文件存储模式 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_DATABASE` / `MYSQL_USER` / `MYSQL_PASSWORD` | — | 数据库连接（各服务共用库 `vein_talk`） |
| `MINIO_ENDPOINT` / `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | — | MinIO 连接与凭据 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | — | Redis 连接（`CACHE_MODE=redis` 时使用） |
| `LIVEKIT_URL` / `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | — | LiveKit 连接与密钥（与 livekit.yaml 中 keys 一致） |
| `GATEWAY_NODE_NAME` / `VEIN_NODE_ID` | — | 节点标识 |

### 厂商离线推送（可选）

在 `.env` 或服务环境变量中配置各厂商参数（在各厂商开放平台注册后获取），未配置的厂商不启用推送：

```
PUSH_HUAWEI_APP_ID / PUSH_HUAWEI_APP_SECRET
PUSH_XIAOMI_APP_SECRET
PUSH_OPPO_APP_KEY / PUSH_OPPO_MASTER_SECRET
PUSH_VIVO_APP_ID / PUSH_VIVO_APP_KEY / PUSH_VIVO_APP_SECRET
PUSH_HONOR_APP_ID / PUSH_HONOR_CLIENT_ID / PUSH_HONOR_CLIENT_SECRET
PUSH_APNS_KEY_FILE / PUSH_APNS_KEY_ID / PUSH_APNS_TEAM_ID / PUSH_APNS_PRODUCTION
```

## 六、端口对照表

| 端口 | 组件 | 说明 |
|------|------|------|
| 30110 | im | 客户端 HTTP API（`/vein-gateway/`）与 WebSocket（`/vein-gateway/access`） |
| 30113 | im | 管理后台 API（`/vein-im-manage/`） |
| 30114 | im | 公众平台 API（`/vein-im-platform/`） |
| 3306 | MySQL | 数据库 |
| 6379 | Redis | 缓存 |
| 9000 / 9001 | MinIO | API / 管理控制台 |
| 7880 | LiveKit | HTTP API |
| 7881 | LiveKit | WebRTC TCP（UDP 不通时回退） |
| 7882 | LiveKit | WebRTC 媒体（UDP，**核心通道，需对外开放**） |
| 10101 / 10102 | Nginx | HTTP / HTTPS 站点（内部监听端口，可按需改为 80/443） |

> 容器为 host 网络模式，以上端口直接占用宿主机，请确保无冲突；对外防火墙只需放行 Nginx（80/443）、30110（未走 Nginx 时）、7881/7882（音视频）及 9000（MinIO 直传时）。

## 七、升级指南

1. 导入新版本镜像：`docker load -i vein-talk-aio:<新版本>-<架构>.tar.gz`
2. 修改 `docker-compose.yml` 中 `image:` 为新版本标签
3. `docker compose up -d` 重建 im 容器
4. **表结构无需手动处理**：服务启动时自动检测并安装新增表、字段、索引

## 八、常见问题

| 现象 | 处理 |
|------|------|
| 端口被占用 | host 网络模式下检查 3306/9000/6379/30110 等是否已有其他服务 |
| MySQL 健康检查失败 | 首次启动会初始化数据库，耐心等待；查看 `docker logs vein-mysql` |
| 客户端连不上 | 检查 `SERVER_URL` 是否为客户端可访问的对外地址；检查防火墙 30110/80 |
| 图片/文件无法上传下载 | 检查 `MINIO_UPLOAD_ENDPOINT` / `MINIO_DOWNLOAD_ENDPOINT` 是否为对外地址 |
| 音视频通话不通 | 检查 7881/7882 是否对外开放；`LIVE_URL` 与 `livekit.yaml` 中 `node_ip` 是否为公网 IP |
| 收不到离线推送 | 检查对应厂商推送参数是否已配置且与客户端打包的厂商配置一致 |
